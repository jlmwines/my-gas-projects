# Bundle Web Sync + Slot Category Rules

Replaces the bundle "web → ops" machinery with a safe design: a dedicated web snapshot (`WebBundles`), per-bundle writes that can never touch other bundles, and a required category on every slot ("any wine" is no longer valid). Status: **draft; reviews 1-4 folded in 2026-11-01; awaiting user approval.** Nothing built. Prompted by the 2026-10-30 incident (14 bundles wiped to 1, restored by hand from version history).

## 2. Current-state findings (code-traced, live = repo: no bundle file changed since 2026-08-27)

1. **The wipe.** `BundleService.reimportAllBundlesBatch` (`BundleService.js:1968`) clears every data row of `SysBundles` + `SysBundleSlots` (`:2106-2129`) and writes back only its input. Callers: toolbar Update Composition (all from `WebProdM`), editor Update from web (`WebAppBundles.js:655`, one bundle), nightly `refreshBundleComposition` (`HousekeepingService.js:782`).
2. **Pull writes product data.** `WooProductPullService.pullBundleProducts` (`:571`) writes woosb + discount fields into `WebProdM`/`WebXltM` by reading and rewriting each whole sheet (`:679-695`). It never writes the bundle sheets, so it cannot add or restore a bundle.
3. **Bundle state is read from product sheets.** Compare/needs-push (`buildExportTable`, `:2392`) reads the web side from `wpm_WoosbIds`/`wxm_WoosbIds`; displayed discount from `WebProdM` woosb fields (`_buildBundleDiscountMap`, `:204`); editor descriptions from `WebProdM`/`WebXltM` (`WebAppBundles.js:102-145`).
4. **Nightly rebuild overwrites ops.** Every night ops compositions are reset to `WebProdM`; slot criteria are carried by (bundle, SKU) (`:1984-2004`), so a changed, unexported slot loses its criteria.
5. **"Any category" has no filter.** `_matchesSlotCriteria` (`:871`) skips the category test when blank, so any published in-stock product qualifies (liqueur, accessories, gifts). The same predicate drives the editor picker, Maintain/Re-roll and the deficiency check.
6. **No lock on bundle writes.** Edits address rows by `rowNumber` from a 60 s module cache (`BundleService.js:15`; `:469`, `:638`, `:704`). `LockHelpers.withScriptLock(context, timeoutMs, fn)` is the one global script lock, shared with job-queue claim (`OrchestratorService.js:535`, 5 s) and sync state (`SyncStateService.js:93`, 30 s); it returns `null` on timeout (`LockHelpers.js:21-23`) and is not re-entrant. `ConfigService.setConfigLocked` takes the same lock; nesting it is a documented hang (`ConfigService.js:276-280`). Bundle functions call each other (`duplicateBundle` → `createBundle`/`createSlot`, `:2155-2187`; `saveComposition` → update/create/deleteSlot, `:744-768`), and the generator interleaves picks with writes (`assignProductToSlot` at `:1293,1323,1347`, then `updateBundle` `:1390`).
7. **Doc drift / dead code.** `checkBundleHealth` is called only by Review, though comments and `WORKFLOWS.md` say housekeeping. `ProductImportService._processBundleProducts` has no caller. `sb_Type` is always `'Bundle'` though `DATA_MODEL.md` says derived. `WebCat` lookup lists Rosé twice; several `SysCategories` HE names start with a tab.

Facts the design relies on: HE woosb products carry the EN id in `translations.en` (full pull, `WooProductPullService.js:201,472`; not yet confirmed on `type=woosb` responses, see §4B); `fetchBundleProducts(lang)` passes `type=woosb` but does not re-check `p.type` (`WooApiService.js:286-293`; the only guard today is inside `_upsertBundleFieldsToMaster`, `WooProductPullService.js:669-677`, removed by §4H); the full product pull also refreshes `wpm_WoosbIds` daily (`WooProductPullService.js:169-178`); export reuses each slot's woosb token from `sbs_SlotId = <bundleId>-<token>` (`:2280-2286`), but editor-created slots are stored as bare `SLOT-…` until a web rebuild; `WebProdM` holds EN rows only; 14 woosb bundles today.

## 3. Rules (user, 2026-10-30)

- Bundle sheets are the only authority for bundle state. `WebProdM`/`WebXltM` are product data; bundle code reads them only for per-wine facts (WC id, price, title, categories, stock) and never writes them.
- Pull from Web pulls bundle data and never alters product data.
- Every operation works on one bundle without touching any other bundle.
- Maintenance (common) and hand edits (rare) are exported by the admin immediately after the change and verified by Pull + Review; export stays the existing manual step. No reliance on housekeeping to repair bundle state.
- Every slot names a category; "any wine" is not a valid slot (user 2026-11-01).

## 4. Design

**A. `WebBundles` = the web snapshot.** The blank tab gets a schema (`schema.data.WebBundles`, prefix `wb_`, key `wb_BundleId`): `wb_BundleId` (EN id), `wb_HeId`, `wb_NameEn`, `wb_NameHe`, `wb_Status` (EN WC status), `wb_WoosbIdsEn`, `wb_WoosbIdsHe`, `wb_Discount`, `wb_DiscountAmount`, `wb_CustomPrice`, `wb_DisableAutoPrice`, `wb_ShortDescEn`, `wb_LongDescEn`, `wb_ShortDescHe`, `wb_LongDescHe`, `wb_PulledAt`. Plus a `system.sheet_names` entry. It mirrors the website; only the snapshot refresh writes it.

**B. Snapshot refresh + Pull from Web.** The refresh fetches EN + HE woosb products and joins HE to EN by `translations.en`. Fetching and validation happen before any lock is taken. It aborts with no write if: either fetch throws; EN returns zero or more than a sane cap (50); any returned product is not `type === 'woosb'` (the type guard moves here from the removed `_upsertBundleFieldsToMaster`; today's code also accepts legacy `'bundle'`, `WooProductPullService.js:676`, but bundles are stable woosb products, so anything else is treated as damage and aborts); HE returns zero; two HE products map to the same EN id; any returned HE product lacks its `translations.en` link (an orphan HE bundle that cannot be joined); any non-empty woosb value parses to `{}` (`_parseWoosbJson` returns `{}` both on failure, `:1819-1822`, and for an empty string, `:1799`); or a sync is active (keep the guard at `WooProductPullService.js:578-587`: sync immediately precedes bundle review daily, and bundles can't be maintained before sync updates inventory, user 2026-11-01). The reverse case, an EN bundle that no HE product links to (not yet translated), does not abort: its row is written with blank HE fields and a warning. On success it rewrites `WebBundles` whole (a mirror). **Pull from Web** = refresh, then in the bundle sheets: **create** any web bundle missing from ops (bundle row + slots from the snapshot, slot ids `<bundleId>-<token>`, status publish → Active else Draft as today, `WebAppBundles.js:641`); **update names only** (`sb_NameEn/He`) on existing bundles; never change an existing composition or status (status is ops-owned, e.g. Archived, `AdminBundlesView.html:146`). **A non-Archived ops bundle absent from the web is a serious fault, not routine** (bundles are stable and maintained daily, user 2026-11-01): it is never deleted, and is reported as an error in the Pull result and raised through the existing failure-alert path (helper named at build time), separate from the needs-push count. Names go through the safe write (E). Writes nothing to `WebProdM`/`WebXltM`. Then push-status refresh. A new controller `WebAppBundles_pullFromWeb` replaces `WebAppBundles_pullBundleProducts` (client call `AdminBundlesView.html:1553`). UI response keeps the current shape (`res.success/res.message`, `AdminBundlesView.html:1536-1546`); the success handler, which today only calls `syncPushStatus()` (`:1547`), also reloads the list and stats (`loadBundleList()`/`loadStats()`) so created bundles appear, and the hint text (`:1544-1545`) is rewritten.

**C. Compare / needs push.** `buildExportTable` compares each ops bundle's serialized woosb against `wb_WoosbIdsEn/He`; Archived bundles are excluded; a non-Archived ops bundle with no snapshot row is the "missing from web" fault (§4B), not a needs-push row. An empty or missing `WebBundles` means "unknown": `buildExportTable` returns an `unknown` flag; `refreshBundlePushStatus` then returns early without writing the status cache or touching the push task (today a 0 count overwrites the cache, `HousekeepingService.js:1590`, and closes the task, `:1605-1606`), and `WebAppBundles_buildExportTable`/`exportBundlesToSheet` (`WebAppBundles.js:937`, `:957`) refuse to build or close the task (`:964`), showing "Pull from Web first". SKU→EN id, EN→HE id and stock stay on `WebProdM`/`WebXltM`. Discount and editor descriptions read `WebBundles`. The bundles view shows `wb_PulledAt` as "Web snapshot: <time>".

**D. Restore to web version** (replaces editor "Update from web" and toolbar "Update Composition"). Editor button, open bundle only. Refreshes the snapshot first (so an export since the last Pull is not undone), then rebuilds the bundle's slot rows from its `WebBundles` row, slot ids `<bundleId>-<token>`. Slot criteria are carried by woosb token (strip `<bundleId>-` on both sides), then by SKU (the fallback if WPClever does not keep bare `SLOT-…` keys); unmatched web slots get blank criteria. `sbs_HistoryJson` carries over with the replaced SKU's open entry closed and a "Restore to web version" entry appended for the restored SKU; `sbs_LastRotated` carries over. Keeps `sb_MinTotal/MaxTotal/LastGenerated`; clears `sb_GenFlags` (a display-only post-run self-check, `AdminBundlesView.html:909-944`). Used to undo an unwanted re-roll.

**E. Safe write primitive** (`_replaceBundles(bundleRowsById, slotRowsById)`), the only **bulk** rewrite (Pull create, Restore to web version): read both sheets fresh, keep every row whose bundle id is not a target, substitute the targets, write, clear any trailing rows left when the total shrinks (as the old code did, `:2121-2129`), then re-read and assert every non-target row is unchanged, keyed by `String(id)` (sheet values come back as numbers) and comparing normalized values (`Date` → `getTime()`, everything else → `String`); on mismatch, write back the pre-write contents and fail. The per-row primitives (`createBundle`/`createSlot` `appendRow` at `:446`/`:615`, `deleteBundle`/`deleteSlot` `deleteRow`, `duplicateBundle`, `saveComposition`) stay, and are safe because they only run under an entry-point lock after a fresh read.

**Locking: one layer only, at entry points.** Each `WebAppBundles_*` controller that writes, and the housekeeping/Pull callers, wrap their whole write in `withScriptLock('bundles-write', 30000, fn)` with `clearCache()` + fresh read first so `rowNumber` is current. `fn` returns `{ok: true, value}`, so only a bare `null` means lock timeout (wrapped functions legitimately return `null`, e.g. `assignProductToSlot`/`updateSlot` on a missing slot, `:790-797`, `:631-634`). Exception: the all-bundle Maintain run locks inside its per-bundle loop (`BundleService.maintainBundles`, `:1417`), below the `WebAppBundles_generateCompositions` controller. Internal primitives (`createBundle`, `createSlot`, `updateSlot`, `assignProductToSlot`, `_replaceBundles`, etc.) never lock, so nested calls cannot deadlock. Entry points: Pull, Restore to web version, Maintain, Re-roll, Save composition, `WebAppBundles_applyReplacements` (`:486`), `WebAppBundles_assignProductToSlot` (`:433-453`), slot/bundle CRUD controllers (`:200-365`), create/delete/duplicate bundle. A `null` (lock timeout) result is a failure shown to the user, never a silent skip. Never calls `setConfigLocked` inside the lock; push-status refresh runs after release.

**Generator refactor (compute, then write).** Maintain/Re-roll today write as they pick. They change to: pick every slot's product in memory first (no lock), then apply all of one bundle's writes in a single locked call that first re-checks each slot's starting SKU and skips (and reports) any slot changed since the pick, so a concurrent Save is never overwritten. Maintain-all locks per bundle, not for the whole run, so the job-queue claim (5 s wait) is never starved. Re-roll is per bundle only (editor); the no-id all-bundles path of `rerollBundles` (`:1473`) is removed.

**F. Toolbar scope.** No selection checkboxes (D3). Toolbar Maintain acts on all (already only on deficient bundles); no toolbar Re-roll (all-bundle re-roll is not a real use, user 2026-11-01); editor buttons act on the open bundle.

**G. Category rules in `_matchesSlotCriteria`** (so picker, generator and deficiency check agree):
1. **Blank `sbs_Category` is invalid (user 2026-11-01)** on Product slots (`sbs_SlotType = Product`; Text slots carry no category and are exempt). A Product slot with no category matches nothing: Maintain/Re-roll skip it and report it, the editor picker shows no candidates, and `checkBundleHealth` flags the bundle "Needs attention" with a "slot has no category" reason. None are expected once D4 is done. (`sbs_Category2` may stay blank.)
2. **Semi-Dry exclusion (user 2026-11-01):** a product tagged Semi-Dry is eligible only if the slot names Semi-Dry in `sbs_Category` or `sbs_Category2`. Applies to every slot; this keeps "Rosé | Semi-Dry" and white/semi-dry wines out of plain Rosé/White slots.
3. Category 1 and 2 are both required (AND, `BundleService.js:873-874`): a Rosé + Semi-Dry slot fills only with semi-dry rosés. Category names are matched after Unicode normalization and trimming on both sides (`WebCat` lists Rosé twice; possible Rose/Rosé variants).
4. Slots whose current product no longer matches show "Needs attention" once `checkBundleHealth` runs (it writes `needs_update_status`, `HousekeepingService.js:1776`; called by Review only).
5. Bundles created by Pull (§4B) arrive with blank slot categories and are flagged by rule 1 until the admin sets them.

**H. Removed.** `reimportAllBundlesBatch`, `WebAppBundles_reimportAllBundles`, `WebAppBundles_updateComposition`, both Update buttons and handlers, both housekeeping phase-3 bundle tasks, `refreshBundleComposition` and `refreshBundlePushStatus` (`HousekeepingService.js:782-783`; the `refreshBundlePushStatus` function stays, called after Pull and by its UI controllers `WebAppBundles.js:394,1034`), `pullBundleProducts` + `_upsertBundleFieldsToMaster` (keep the exported `woosbIdsString`, used by `WooProductPullServiceTest.js`), `importBundleFromWooCommerce` + its controller and dead `_processBundleProducts`.

**I. No nightly bundle work (user 2026-11-02).** Housekeeping does nothing with bundles: no snapshot refresh, no push-status refresh. The snapshot and needs-push are refreshed by the admin's own Pull after each export (§3), the only admin touches bundles, and deficiency checking is Review's job against post-sync inventory.

## 5. Decisions

- **D1 — decided (user 2026-11-01):** no "any wine" slots and no everyday default; every slot names a category, blank is flagged (§4G.1); Semi-Dry excluded unless the slot names it (§4G.2).
